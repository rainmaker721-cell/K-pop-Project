# APP 복원·대조 보고서

> 제품 정의: 이 프로젝트는 Vision 앱이 아니다. 실물 K-Pop 포토카드를 스캔하고, 처리된 카드를 대형 Android 패드에 전시하는 전용 제품이다.

## 1. 조사 결과

### GitHub 저장소

- 저장소: `rainmaker721-cell/K-pop-Project`
- 기본 브랜치: `main`
- 확인된 커밋: 최초 커밋 1개
- 원격 저장소에 있던 파일: Android/Gradle용 `.gitignore` 1개
- 소스 코드, Gradle 설정, 이슈, 추가 브랜치는 원격에 존재하지 않았음

따라서 원격 코드를 단순 수정하는 방식으로는 복원할 수 없었고, 과거 대화의 요구사항을 기준으로 프로젝트를 재구성했습니다.

### 과거 대화에서 확인한 방향

- 실물 포토카드 입력용 USB 스캐너와 Android 기반 대형 전시 패드
- `app`, `core`, `feature-scan`, `feature-upscale`, `feature-display`, `feature-admin` 다중 모듈
- 스캔 없이도 폴더/로컬 이미지로 전시 가능
- `Preparing → Display` 상태 전환
- 샘플 이미지 목록과 선택 전시
- 화면 회전 상태 유지
- 핀치 확대/축소 및 드래그
- 외부 온라인 업스케일을 먼저 고려하고, 이후 온디바이스 모델로 교체 가능한 경계
- 향후 USB 스캐너, 보안 저장, 관리자 메뉴, 장시간 안정화 추가

## 2. 실제 중단 지점

과거 대화에서 사용자가 마지막으로 요구한 내용은 다음 두 가지였습니다.

1. 전시 화면을 상태바와 내비게이션 바까지 숨기는 진짜 전체화면으로 만들 것
2. 목록 복귀는 전시 화면 하단의 작은 아이콘으로만 가능하게 할 것

당시 답변에는 교체용 `DisplayScreen` 코드가 제안됐지만 적용·빌드 성공 확인이 없었습니다. 또한 제안 코드에는 별도 Material Icons 의존성 누락 가능성, 문자열 기반 drawable 탐색, 시스템 뒤로가기 허용, 이동 범위 무제한 등의 위험이 있었습니다.

## 3. 이번에 복원한 범위

| 영역 | 상태 | 구현 내용 |
|---|---|---|
| 프로젝트/빌드 | 완료 | Gradle Wrapper, AGP, Kotlin, SDK 설정과 6개 모듈 복원 |
| 스캔 시작 화면 | 완료 | 스캐너 상태, 테스트 스캔, 최근 스캔/데모 카드 |
| 테스트 스캔 | 완료 | 단일 포토카드 이미지 입력, URI 권한·목록 유지, 자동 전시 |
| 준비 상태 | 완료 | 처리기 경계를 거치는 `디스플레이 준비중` 화면 |
| 전체화면 | 완료 | 시스템 바 숨김, 화면 켜짐 유지, 종료 시 원상복구 |
| 전시 조작 | 완료 | 핀치 확대/축소, 드래그, 이동 경계, 더블 탭 |
| 복귀 정책 | 완료 | 시스템 뒤로가기 소비, 하단 버튼만 복귀 허용 |
| 슬라이드 쇼 | 완료 | 전체 이미지 8초 자동 순환 |
| USB 스캐너 | 후속 선정 | `UsbScannerGateway` 경계만 유지하고 장비·SDK 선정 후 구현 |
| AI 업스케일 | 경계만 복원 | `UpscaleProcessor`; 현재는 원본을 정직하게 통과 |
| 관리자/DRM | 미구현 | 운영 정책과 인증·보안 요구사항 필요 |

## 4. 오류 가능성과 대응

- **원격 소스 부재**: GitHub에는 코드가 없었으므로 과거 대화에서 확인된 범위만 재구성했습니다.
- **동적 리소스 탐색 오류**: 과거의 `getIdentifier()` 대신 타입 안전한 리소스 ID/URI 모델을 사용합니다.
- **아이콘 의존성 누락**: 별도 아이콘 패키지 없이 Canvas로 복귀 아이콘을 그립니다.
- **이미지 OOM 위험**: 로컬 이미지는 화면 용도에 맞게 최대 크기를 제한해 디코딩합니다.
- **끝없는 이미지 드래그**: 확대 배율과 뷰포트 크기를 기준으로 이동을 제한합니다.
- **URI 접근권한 상실**: 가능한 경우 읽기 권한을 영구 보관하며, 접근 실패 시 오류 메시지를 표시합니다. 일부 문서 제공자는 영구 권한을 지원하지 않을 수 있습니다.
- **첫 몰입형 실행 안내**: Android 에뮬레이터/기기에서 최초 한 번 시스템 자체의 `Viewing full screen` 안내가 표시될 수 있습니다.
- **대형 패널 차이**: 에뮬레이터 검증은 완료했지만 실제 27인치 패널의 번인, 발열, 터치 정확도, 장시간 메모리는 별도 검증이 필요합니다.

## 5. 구조 개선점

- 화면에서 파일·스캐너·AI API 세부 구현을 분리했습니다.
- 업스케일 API가 없어도 거짓 성공 표시 없이 원본 전시가 가능합니다.
- 이미지 소스를 `Resource`와 `LocalUri`로 명시해 이후 스캐너 파일이나 캐시 파일을 추가하기 쉽습니다.
- 순수 계산인 확대/이동 제한을 `core`로 옮겨 단위 테스트할 수 있게 했습니다.
- 전시 화면 진입/종료 시 시스템 UI와 화면 켜짐 플래그를 대칭적으로 적용·복원합니다.
